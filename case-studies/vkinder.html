VKinder

A live child-health data platform for parents and practitioners, comparing child development, services and environmental conditions across 361 Greater Melbourne areas. Monash Industry Experience capstone and finalist in the Monash DS&AI Showcase 2026.

361 areas · 31 public sources · 4.1-point model error vs 6.4 without a model · calibration slope 0.99

Data flow and architecture

Data scientist in a team of six. I built the data pipeline, models and data APIs; teammates built the frontend and run production. The source repository is private.

  1. 31 public sources: AEDC, ABS Census, environment and services
  2. Geographic harmonisation across 361 areas
  3. Seven quality gates and atomic rollback
  4. Ridge expected vulnerability + E2SFCA access + shortlist stability
  5. Private encrypted AWS RDS PostgreSQL
  6. FastAPI on AWS Lambda with data contracts

Why this project

When a friend and I were looking at places to move, we tried to find useful information about neighbourhood health patterns. We couldn't find something that helped us compare areas clearly. That gap became the starting point for VKinder. The project now focuses on area-level child development, environment and services; it doesn't assess personal health risks.

What went wrong

An earlier shortlist-stability implementation re-ranked only initially eligible areas, overstating stability. The corrected approach reruns the complete search. Weekly refreshes now must pass validity, coverage, key integrity, lineage, reproducibility, freshness and display-completeness gates, or every output file rolls back.

What I’d do differently

Extend evaluation across regions and future releases, and keep uncertainty visible in the “Where to live” shortlist. Small-area shrinkage and stability labels help users interpret rankings without treating them as guarantees.

Failure and limitations

Area-level analysis does not assess individual children or establish causation. Suppressed values remain suppressed and are never imputed. The 2031 tool models service pressure from official population projections.

Scale and evaluation

A ridge model uses ten census measures to estimate expected developmental vulnerability and flag areas doing worse than expected. The selection rule was specified before results. On unseen regions, error was 4.1 points versus 6.4 without a model; calibration slope was 0.99.

Hosting and cost

The documented deployment uses Vercel for the frontend and AWS Lambda, API Gateway and RDS PostgreSQL for the API and data. No hosting-cost or production-latency benchmark is claimed.

Security and privacy

Only area-level public data, with no personal data or generative AI deciding anything about a child. Validated data is stored in private, encrypted AWS RDS PostgreSQL and served through API data contracts.

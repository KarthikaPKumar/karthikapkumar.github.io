Cloud-native wildlife detection API · 2025

CloudEcho

A wildlife-detection API serving YOLOv8 through detection and annotated-image endpoints, deployed on Kubernetes on Azure with Terraform-defined infrastructure.

7.58 req/s at one pod → 32.32 at four → 32.68 at eight

Data flow and architecture

Implemented model serving and Azure Kubernetes deployment with one to eight replicas, health probes, CPU and memory limits.

  1. Submitted image
  2. FastAPI request validation
  3. Decode and resize
  4. YOLOv8 / ONNX inference
  5. JSON detections or annotated image
  6. Kubernetes health and readiness probes

Why this project

An image model needs an API, validation and a deployment path before another application can use it. This repository explores that surrounding engineering.

What went wrong

Adding replicas stopped delivering proportional gains: eight pods reached 32.68 requests/s, only slightly above 32.32 at four. I reported the plateau as the scaling limit. CPU inference runs in a thread pool off the FastAPI event loop.

What I’d do differently

Profile the bottleneck behind the four-to-eight-pod plateau and evaluate task-specific detection quality before making broader performance claims.

Failure and limitations

Throughput plateaued beyond four pods in the measured workload. These serving results do not establish wildlife-detection accuracy or current endpoint availability.

Scale and evaluation

Locust workload: 70% detection and 30% annotation. Throughput rose from 7.58 requests/s at one pod to 32.32 at four, then plateaued at 32.68 at eight.

Hosting and cost

Azure infrastructure is defined in Terraform. No current running cost is claimed.

Security and privacy

Multi-stage, non-root Docker image with Kubernetes readiness and liveness probes and resource limits.
